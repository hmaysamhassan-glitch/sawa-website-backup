# Sawa Editorial Experience

## North star
A Sawa article should be useful enough for search, extractable enough for answer engines, and designed well enough that Ziad could proudly feature it in a LinkedIn post.

## Every article needs
1. A narrow primary question or thesis.
2. A direct Sawa answer near the top when appropriate.
3. One memorable visual concept.
4. At least one useful artifact: calculator, scorecard, decision tree, template, diagram, comparison, simulator, annotated example, or dataset.
5. At least one Sawa-specific insight, framework, or point of view.
6. Credible sources for factual claims.
7. Internal links to related Sawa pages.
8. A shareable headline / visual moment.

## Avoid generic AI writing
Never use:
- “In today's fast-paced digital landscape”
- “Whether you're X or Y”
- generic five-tip intros
- fake anecdotes
- invented statistics
- repetitive three-part rhetorical patterns
- conclusions that simply restate every section
- excessive em dashes
- filler definitions a professional reader already knows

Write with specificity. Use short and long paragraphs naturally. State tradeoffs. Say when the answer depends on context.

## Experience patterns
Choose the format that best fits the question:
- decision query → quiz / decision tree
- numeric/economic query → calculator
- process query → scrollytelling / timeline
- comparison query → toggle + decision table
- copy/design query → before/after or live preview
- system query → node map / flow diagram
- benchmark query → data visualization

Do not force the same template on all articles.

## Distribution
Every article should include a short “shareable finding” or visual that can become a LinkedIn carousel/post without redesigning the entire story.
